# aoe1web

Browser remake of Age of Empires 1 (target: AoE1 + Rise of Rome 1.0a), deterministic lockstep, 2-player rooms by invite code. npm-workspaces TypeScript monorepo, Node >= 24.

## Commands
- `npm ci`: install. After it, once per machine: `npx playwright install chromium firefox webkit` (needed by `test:e2e` only; the determinism test runs all three).
- `npm run dev`: server (`:8787`, env `PORT`) + client (`:5173`, env `CLIENT_PORT`).
- `npm run build`: client and server bundles.
- `npm run start` (after `npm run build`): production, one origin. The server (`PORT`, default 8787; env `ASSETS_DIR` the pack, `CLIENT_DIR` default `apps/client/dist`) serves the built client at `/` and `/bundle/*` (content-hashed, immutable cache), the pack at `/assets/*` (`ETag` + `Last-Modified`, `no-cache`, so a revalidation is a 304), `/health` and the relay on `/ws`; the client reads `/ws` (wss on https) and `/assets` from the page's own origin, so no proxy is needed. `npm run test:e2e:prod` runs the lobby and smoke specs against it (`PROD_PORT`, default 8987). Types and cache rules: `apps/server/src/assets.ts`.
- `tools/deploy/update.sh`: deploy local `main` to the public site aoe.signalsradar.space (VM deche, systemd, Cloudflare tunnel); what runs where, logs, rollback: docs/deploy.md.
- `npm run check`: tracked-file guard, ESLint, typecheck, unit tests. Run before every commit.
- `npm test`: unit tests (Vitest) in every workspace; one workspace: `npm test -w @aoe/sim`.
- `npm run test:e2e`: Playwright (`e2e/playwright.config.ts`); builds the bundles and serves them (`vite preview` + the bundled server, not the dev server: a page loads a few files, not hundreds of transformed modules; the client bundle lives in `/bundle` because `/assets` is the server's pack) on `:5273` / `:8887`. One worker by default (every test runs two browsers over wall-clock-paced lockstep): more with `npm run test:e2e -- --workers=3`, a file filter with `npm run test:e2e -- determinism` (the script is `cd e2e && playwright test`, so one `--` is enough; a flag without it is eaten by npm). Waits are on state (a turn reached, a unit trained) with no cap of their own; the stall bound is the test timeout in `e2e/playwright.shared.ts` (240 s; research sets 600 s), so a loaded machine makes the run slow, not red. `determinism` hashes one sim replay in Node, Chromium, Firefox and WebKit; on macOS it skips Firefox (cannot start, see Traps) and says so, in the Linux image all four run.
- `npm run test:e2e:latency`: `e2e/tests/latency.spec.ts` (wall-clock click-to-action, RTT change), its own config (`playwright.latency.config.ts`), NOT part of `test:e2e`. Run it by hand on an idle machine (`uptime`, load well under the core count, nothing else browsing): its numbers are real milliseconds and fail under load.
- `npm run test:soak`: `e2e/tests/soak.spec.ts` (its own config `playwright.soak.config.ts`, NOT part of `test:e2e`; ~10 min on a quiet machine, more under load): two clients join by invite code on a seeded Hill Country map (Medium, Score victory, random civs), and a bot per client (`Bot` in the spec, seeded) issues 2-4 varied commands (work, build incl. Farms, queue, move incl. onto hills, attack, research, repair, stop, stand-ground, cancel) every 2 turns through `window.__game.issue`, for `SOAK_MINUTES` (default 20) of game time (`gameTime()`); a game that ends cleanly (conquest) before that is not a failure: both clients leave it and play a new game (new invite code, next derived map and command seed, printed per game) until the summed game time reaches `SOAK_MINUTES`. It fails on the first `desync()` the relay reports (`desync at turn N: host hash …, guest hash …`) and compares both clients' checksum of the last sync-check turn (every 4th) itself. Its first test checks the detector: `&perturb=N` (debug, one client only) changes that client's food after turn N and the relay must report the first sync-check turn after N (a multiple of 4). Env: `SOAK_MINUTES`, `SOAK_SEED` (first game's map seed, default random, printed), `SOAK_BOT_SEED` (its command seed); a failure is replayed with the two seeds printed for the game that failed. Same port and load rules as `test:e2e`.
- `AOE1_DIR=<install> npm run assets:import`: build the pack (~8 s, ~100 MB). Then `AOE1_DIR=<install> npm run test:e2e:real -w @aoe/e2e` (local-only screenshot to `assets-local/screenshots/`).
- `AOE1_DIR=<install> npm run test:golden`: tests against real game files (skipped without `AOE1_DIR`); `@aoe/data` parses `data2/empires.dat` to its last byte.
- `AOE1_DIR=<install> npm run dat:dump -- unit 83`: print a record from `data2/empires.dat` (`unit|tech|graphic|terrain|effect|civ|sound <id>`, `summary`; no vitest).

## Standing rules
- The generated runtime pack in `assets-local/pack/` is tracked so fresh clones have complete map and UI assets. Raw game installations and intermediate imports stay outside Git. `npm run guard` (part of `check`) rejects game files outside the pack.
- The decompiled source (github.com/dcostap/aoe1-decomp) is read to write `docs/spec/`, never pasted into the repo.
- `packages/sim` must not use `Math.random`, `Date` or transcendental `Math.*` (sin, cos, tan, pow, exp, log, atan2, ...; `Math.sqrt` is allowed, it is correctly rounded). ESLint enforces it (`eslint.config.js`); sim code uses its own deterministic helpers.
- Game numbers come from the original `empires.dat`, not wiki pages alone.

## Traps
- Playwright's Firefox (159, v1572) does not start on macOS 27 ("Could not find profile folder"). Run the e2e suite in the matching Linux image: `docker run --rm --name aoe1online-<worktree>-pw -v "$PWD":/src:ro mcr.microsoft.com/playwright:v1.65.1-noble bash -c 'mkdir /work && tar -C /src --exclude=node_modules -cf - . | tar -C /work -xf - && cd /work && npm ci && npm run test:e2e -- determinism'`.
- TypeScript is pinned to 6.0.x: typescript-eslint 8.x does not accept TypeScript 7 yet.
- `window.__game.applied()` lists a batch when it is received; `World.addBatch` runs it `COMMAND_DELAY_TURNS` (2) turns later. An e2e that waits on `applied()` must also wait 2 more turns before reading unit state (`e2e/tests/move.spec.ts` `settle`).
- A new `window.__game` hook must also be typed in `e2e/globals.d.ts`, or `npm run check` fails on the e2e typecheck.
- The step size follows the measured frame time, as in the original (turn-timing.md §4, §8.1): on a loaded machine or software WebGL (the Playwright Linux image) frames take 70-300 ms, the server picks `G` 70-150 and click-to-action grows past 1 s. Wall-clock assertions only hold on an idle machine with a GPU; check `uptime` first.
- `packages/sim/src/trig.test.ts` (sin/cos, default 5 s timeout) times out in the full `@aoe/sim` run when the host's load average is in the hundreds (it shares CPU with the fuzz files); alone it takes ~0.5 s: `npm test -w @aoe/sim -- src/trig.test.ts`. Check `uptime` before treating it as a regression.
- A Playwright file filter is a regex over the absolute path: in a worktree named `*-lobby-*`, `npm run test:e2e -- lobby` matches every spec. Anchor it (`tests/lobby.spec`, `real/real-lobby-settings`).
- `npm run test:e2e` uses fixed ports :5273/:8887 with `reuseExistingServer: false`, so a parallel crew's run (or a stale dev server) makes it fail at startup. Check `lsof -iTCP:5273 -sTCP:LISTEN` first; if it is taken, run the suite in the Docker command above with `--name aoe1online-<worktree>-pw`, and add `--exclude=assets-local` to the tar.
- An e2e "hang" past the test timeout on macOS is a system sleep: Playwright's timeout counts the sleep, and the reported duration equals it. `e2e/global-setup.ts` runs `caffeinate -s -i -w <runner pid>` on darwin to prevent it. To confirm a past failure, check `pmset -g log` for a Sleep→Wake window around it; high load is not the cause.
- `e2e/tests/resign.spec.ts` asserts "Bob resigned." right after the host's `gameResult() !== null`: the chat line lives 8 s, so a check placed after slower waits (the guest's result, sounds) can miss it.
- `World.restore(w.snapshot())` without a JSON round trip hashes differently from `w` even when both snapshots serialise alike (seen with plain test worlds); snapshot tests restore `JSON.parse(JSON.stringify(w.snapshot()))` as `diplomacy.test.ts` does.
- The repo has no Prettier config: `npx prettier --write` reflows whole files to 80 columns. Match the surrounding style by hand (lines up to ~160).
